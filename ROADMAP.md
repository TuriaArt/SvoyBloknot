## Осознанно не трогаем (для этого бета-релиза)

Решение: пока оставляем как есть, без изменений — не блокирует релиз, но при желании можно вернуться позже.

- **Протокол `siyuan://`** — используется для ссылок на блоки и внешних интеграций. Переименование в `svoybloknot://` сломает существующие ссылки/интеграции, нужно отдельное решение с миграцией.
- **`SiYuan-Kernel.exe`** — имя бинарника ядра. Завязано в нескольких местах (`build.yml`, `main.js`), плюс переименование сбрасывает репутацию файла у антивирусов «с нуля».
- **`~/.config/siyuan`** — глобальная папка настроек (Linux/macOS). Переименование потеряет настройки уже установленных копий (включая тестовую копию автора).

## Дальше по плану

- **Приоритет: Календарь + Канбан + Дашборд + Excalidraw как встроенные функции (не плагины).** Пользователь считает эти вещи обязательными для любого блокнота — по опыту Obsidian/Logseq/Anytype. Статус на данный момент:
  - Канбан — уже реализован нативно в движке баз данных (`kernel/av`: раскладка Kanban, колонки Checkbox/Date/Relation/Number), доработки не требуются для базовой версии.
  - Календарь — отсутствует полностью, нет даже read-only вида по месяцу/неделе (есть только пикер даты для дневника и для полей типа «Дата»); строить с нуля.
  - Дашборд — отсутствует полностью, нет ни системы виджетов, ни стартовой страницы, отличной от справки; строить с нуля.
  - Excalidraw (рисование от руки/диаграммы) — в SvoyBloknot отсутствует полностью. Оказалось проще, чем ожидалось: официальная библиотека [excalidraw/excalidraw](https://github.com/excalidraw/excalidraw) (MIT, без конфликта с AGPL-3.0) — готовый React-компонент `@excalidraw/excalidraw`, сцена хранится как обычный JSON, экспорт в PNG/SVG уже встроен. Не «писать движок рисования», а «встроить готовый виджет как новый тип блока» — но фронтенд SiYuan не на React, так что React придётся смонтировать «островком» только под этот блок (проверенный паттерн — тот же способ использует плагин `sigma.excalidraw`, который уже работает в SvoyAgent/Meridian поверх Vue-приложения). В SvoyAgent (сестринский проект) этот плагин уже установлен и работает — но это другая система плагинов (Tauri/Sigma), сюда напрямую не переносится, только сама идея интеграции через npm-пакет.
  - Встроенная система задач (агрегация чекбоксов по всем документам/блокнотам сразу) технически близка к этой же теме — отталкивались от стороннего плагина task-horizon, но своя версия задействует движок `kernel/av` напрямую, без хаков поверх блоков.
  - Дизайн ещё не начат, ждёт окончания текущей фазы отлова багов.
- **Встроенный переводчик документов на русский — два уровня, оба решены.**
  - **Уже сделано (release 1):**
    1. Пункт «Перевести на русский» в меню ИИ-действий блока (`app/src/ai/actions.ts`) — работает через уже настроенного ИИ-провайдера пользователя (например, локальный Ollama). Плюс новый ключ `aiTranslateRu` в `ru.json`/`en.json`.
    2. Пункт «Перевести на русский» в контекстном меню при выделении текста в редакторе (`app/src/menus/protyle.ts` для выделения внутри одного блока, `app/src/protyle/gutter/index.ts` для выделения на несколько блоков) — открывает выделенный текст в Яндекс.Переводчике во внешнем браузере. Раньше на выделенном тексте в редакторе правый клик вообще не показывал никакого меню — это первое.
  - **Дальше по плану — полноценный перевод прямо в приложении, без ИИ-агента и без своего сервера.** Изучили несколько путей:
    - ~~LibreTranslate (AGPL-3.0) + модели Argos Translate (MIT), встроенные как отдельный процесс~~ — технически лучший результат (офлайн, свой движок), но у LibreTranslate нет готовых бинарников (только pip/Docker), пришлось бы тащить Python-рантайм или писать свой Go-мост к CTranslate2 (готовых Go-биндингов практически нет, нашли только неподдерживаемый черновик с 0 звёзд) — многодневная работа, плюс ~370 МБ к установщику за пару en↔ru. Отложено, не первоочередной путь.
    - **Рекомендованный путь:** по образцу [Crow Translate](https://github.com/crow-translate/crow-translate) (архивирован, разработка продолжилась под KDE: `invent.kde.org/office/crow-translate`) и его библиотеки **QOnlineTranslator** (GPL-3.0) — дёргать бесплатные неофициальные API Google/Yandex/Bing/LibreTranslate/Lingva напрямую, без ключей, без своего сервера, без прироста размера установщика. Тот же принцип использует и старая Python-библиотека `goslate` (по факту заброшена, но подтверждает, что подход рабочий и проверен временем). UX ориентир — как в плагине `Gazdea/translate-siyuan-plugin`: клик на блок → превью перевода → выбор «Заменить» или «Скопировать», а не слепая вставка.
    - **Честная оговорка:** это неофициальные (не задокументированные производителем) эндпоинты — могут измениться или временно ограничить доступ без предупреждения. На практике так работают многие опенсорс-переводчики годами, но это не гарантия навсегда.
    - Рассмотрели и отклонили: **Apertium** (GPL-2.0, rule-based) — слабое качество для пары en-ru, он заточен под близкородственные языки; **OmegaT** — не движок перевода, а рабочее место переводчика-человека (память переводов, глоссарии), не годится для встраивания.
  Дизайн полноценной встроенной версии ещё не начат, ждёт окончания текущей фазы отлова багов.
- **Одна кнопка «Переместить рабочее пространство» в настройках.** Идея пользователя, найдена реальная боль: существующая функция «Миграция данных» (`app/src/menus/dataMigration.ts`) — это не про переезд папки блокнота на другой диск, а про импорт из Obsidian/Markdown/`.sy.zip`, экспорт конфигурации и ключей синхронизации, пользователь запутался, что верно — это не тот инструмент. Сейчас единственный способ сменить расположение — вручную закрыть приложение, вручную перенести папку через проводник, перезапустить и вручную указать новый путь через `electron/workspace.html` (кнопка «Выбрать» уже есть и открывает нативный проводник — но только выбор уже перемещённой папки, не перенос). Нужна вкладка «Рабочее пространство» в настройках: текущий путь виден сразу, кнопка «Переместить» → открывает проводник → сама копирует данные на новое место, переключает приложение на него и подчищает старую папку — без ручных промежуточных шагов пользователя. Дизайн ещё не начат.

## Не планируется (пока)

- Полноценная замена интерфейса — SvoyBloknot использует родной интерфейс SiYuan как есть, не форкает его ради нового UI (в отличие от SvoyAgent, который форкает Meridian ради своего интерфейса).
- Собственная инфраструктура синхронизации/облака — WebDAV/S3/локальная папка уже покрывают эту потребность без ограничений, писать своё незачем.
